# CS 255 System Analysis and Design

## DriverPass Project

The DriverPass project focused on designing a system for a client who wanted to improve the way students prepare for their driving tests. The client, DriverPass, wanted a system that would allow customers to access online training materials, take practice tests, purchase training packages, and schedule driving lessons. The system also needed to support employees and administrators while staying up to date with information from the DMV.

## What I Did Well

One part of this project that I did particularly well was translating the business requirements into a system design. I was able to identify the different users of the system and determine what functions each user needed. I also used UML diagrams to show how users would interact with the system and how different parts of the system would communicate. This helped turn the client's requirements into a design that developers could understand and implement.

## What I Would Revise

If I could revise one part of my work, I would improve some of my UML diagrams. Although they communicate the major functions and relationships within the DriverPass system, I would spend more time refining the details and making the diagrams as clear and consistent as possible. I would also review the relationships between components to make sure that each diagram communicates the system's behavior efficiently without including unnecessary information.

## Interpreting User Needs

I interpreted the user's needs by reviewing the DriverPass requirements and identifying what customers, employees, administrators, and other users needed to accomplish within the system. I then incorporated those needs into features such as account management, scheduling driving lessons, online training, practice tests, progress tracking, and administrative functions. Considering user needs is important because a system can be technically functional but still unsuccessful if it is confusing or does not solve the problems users actually have. Designing around user requirements helps ensure that the final system is useful, accessible, and effective.

## My Approach to Software Design

When designing software, I first try to understand the problem the system is supposed to solve and identify the needs of the client and users. From there, I break the system into smaller requirements and use tools such as use case, activity, sequence, and class diagrams to visualize how the system should operate. In future projects, I would continue using an iterative approach by reviewing requirements, creating models, gathering feedback, and refining the design before implementation. This process can help identify problems earlier and create a system that better meets both business and user requirements.
